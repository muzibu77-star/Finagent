# 研报发布前质控预审 Agent：项目计划

## 定位

- **用户**：研究所质控岗；发稿前自查的卖方分析师。
- **痛点**：每篇研报或点评有几十到上百个数字、日期和引述需人工逐条对回出处；质控人手少、点评时效紧；分析师用通用模型写初稿后出现时点错位一类错误。
- **依据**：[调研报告](../compass_artifact_wf-3d398577-d946-572a-91ec-2940d1306db6_text_markdown.md)（由外部模型检索生成）引用的监管处罚事由为“引用信息与原文不一致、数据来源未核实、发布日期错误、底稿缺失”。其中 5 个关键来源已核对原文（见 [result.md](result.md)），其余来源未核实；**没有质控人员的一手访谈。**
- **输入**：稿件草稿＋出处库（公司公告、政策文件、统计数据）。
- **输出**：逐条核查意见（一致／不一致并附原文值／找不到依据／口径不明）；稿内前后一致性检查；带出处的修改建议；工作底稿（每个数据的来源、计算方法、核对过程）。
- **不做**：不生成投资观点或评级，不对外发布；查不到依据的条目交给人，不下结论。
- **衡量**：错误检出率、误报率、可自动核对比例、交给人的比例。
- **部署假设**：未发布稿件属敏感信息，目标是可私有化部署的开源模型；基座与硬件不预设，由阶段 4 的开发集实测决定。

## 已定的设计决定（用户 2026-10-13）

- **多智能体**：抽取（只看稿件）、核查（一条断言＋其证据，可检索／读原文／计算）、一致性（只看断言列表）、修订（只能写修改建议，不能改核查结论）；汇总与底稿由代码生成。是否优于单 Agent 须在同一评测集上对照后决定保留。
- **框架**：编排用 LangGraph，模型调用、结构化输出、工具与检索器用 LangChain 接口。受控计算、出处检索、任务持久化与审核留痕不重写，以薄适配接入；LangGraph checkpoint 只管流程状态，审核记录与报告仍由 `Store` 保存。
- **PDF 解析**：引入 MinerU 解析表格结构，并要求每个单元格可映射回原页位置（`Evidence` 已有的页码、表格、行、列、位置框字段）。
- **不做蒸馏**：训练标签来自“正确稿件注入错误”，不以 API 模型为教师。

## 分阶段计划

状态：阶段 0、阶段 1 已完成（2026-10-14），验收依据与遗留缺口见 [result.md](result.md)；阶段 2 起未开始。

每个阶段回答一个问题；答案不支持继续时停下调整，不向后堆叠。数量与结果只在 [result.md](result.md) 记录。

| 阶段 | 交付 | 前置条件 | 验证方法与验收标准 |
|---|---|---|---|
| **0. 定义任务** | 核实调研关键来源；错误分类；断言字段与四种核查结论的定义（用户已确认，记录见 [result.md](result.md)） | 无 | 关键来源逐条打开核对原文，无法核实的标明；每类错误有监管事由或实例对应；断言与结论的定义能由两段示例稿件无歧义地标注 |
| **1. 建出处库** | 20—50 家发行人的中文年报与公告（披露日、版本、哈希）；表格解析为带指标、期间、单位的事实；政策文件与统计数据（用户决定与定期报告同批入库） | 阶段 0；来源与使用范围核实；下载预算 | 抽样页与人工核对表格事实的数值、单位、期间；每个事实可回查到原页位置；解析失败与排除原因留存 |
| **2. 建评测集** | 注入错误集（改数、改单位、改年份、引用更正前旧值、算错增速、标错日期）；通用模型写的点评经人工标注的真实错误集；按发行人留出，开发与验收分开冻结 | 阶段 1 | 注入位置与类型可由程序复核；真实错误集给出模型稿件的实际错误率；留出发行人与训练来源无交集 |
| **3. 免训练基线** | 抽取 → 检索 → 代码匹配与重算 → 结论的完整流程；四段归因 | 阶段 2 开发集冻结 | 报告检出率、误报率、交给人的比例及各段失败占比；与“API 模型直接审稿”同题对照 |
| **4. 训练** | 只针对阶段 3 最弱环节训练；候选基座在开发集实测后选定 | 阶段 3 归因完成；训练预算授权 | 单因素对照、预先写明的门槛、配对区间；与 API 模型同题比较；无可靠收益则不采用 |
| **5. 产品化** | 多智能体编排、修改建议、底稿导出、审核页面、MCP 工具、故障测试 | 阶段 3 流程稳定 | 多 Agent 与单 Agent 同集对照；故障不变量通过；导出底稿与核查记录一致 |
| **6. 验收** | 未暴露验收集一次性验收；可选扩展到招股书与问询回复的一致性核查 | 候选冻结 | 协议先于结果封存；结果不再用于调参 |

风险排序：阶段 1 的中文表格解析是最大工程风险；阶段 2—3 是最大方向风险（若通用模型写稿很少出错，或 API 模型加检索已能查出绝大多数错误，训练路线须如实降级为工程与评测项目）。

## 现有代码基础

仓库保留了一套可运行的取证、计算与执行基础，逐模块说明见 [architecture.md](architecture.md)：

- **可直接使用**：受控 Decimal 计算、带原文位置的证据与事实结构、原始 PDF 入库与披露日／版本过滤、神经检索与重排、SQLite 任务持久化、训练入口与多卡后端、近重复检测、配对区间统计、vLLM 客户端与性能测量、表格单元格到原文位置的映射。
- **需要改造**：执行流程（现为“检索 → 计算 → 回答”，要改为“取断言 → 检索 → 匹配或重算 → 给结论”）、本地服务页面与 MCP 工具、中文样例与更正公告案例（改作评测种子）。
- **阶段 4 前需要重写**：训练入口的数据装载与样本准备仍绑定英文问答数据的格式，相关模块暂时保留，届时按核查任务的数据重写并清理。
