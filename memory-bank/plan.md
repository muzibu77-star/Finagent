## 阶段推进与停止条件

- **主线完整保留**：M0 可行性 → M1 基线 → M2 训练对照 → M3 完整 Agent → M4 文档库与时间约束 → M5 多模态与中文 → M6 服务展示。
- M2 因训练资源受阻时，明确记录后可基于 M1 推进 M3；不能将阻塞写成完成。
- M6 可先发布 M3 核心版本，M4、M5 后续增量加入，不删去未完成阶段。
- DPO/GRPO、多 Agent、向量数据库迁移和视觉微调保留为有证据后再立项的可选扩展。
- 不预设固定正确率或提升幅度；新方案无收益时保留基线。必须通过的故障不变量失败时，修复或明确缩小交付范围后重新验收。
- 长任务实施前提供完整命令、预算、产物、进度与恢复位置；由代理执行验收并据实推进依赖步骤（用户于 2026-10-06 明确授权）；每阶段完成只本地提交，最终用户审核后再推送。
